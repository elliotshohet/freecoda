# Security policy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/elliotshohet/freecoda-releases/security/advisories/new) for suspected security vulnerabilities affecting Freecoda desktop, its update delivery, CLI, or hosted service. This reporting channel is enabled for this repository and requires a GitHub account.

Do not open a public issue with vulnerability details or sensitive data. Include the affected version and platform, the impact, and reproducible steps using synthetic files or a minimal non-sensitive example. Redact credentials, tokens, device codes, private repository contents, prompts, and conversation history. Never include a live secret as proof.

Reports are handled through the private GitHub advisory conversation. No response-time or bug-bounty commitment is made by this policy. Do not test against accounts, repositories, or systems you do not control.

## Version information

Use the latest public release and include the exact version when reporting a problem. The initial desktop releases are beta software. Unsigned and unnotarized installer status is documented in the [README](README.md); verify release checksums before opening downloads.

For non-security bugs, use the canonical [Freecoda public issues](https://github.com/elliotshohet/freecoda/issues/new) with a sanitized reproduction and no private code, prompts, keys, or account data. The established private advisory channel stays in the compatibility repository until a separate reporting-channel migration is verified.
